# 剧本：用户的一天（v0.1 模拟）

> 目的：用剧本逼出数据模型、提议格式、冷启动、反馈机制的答案。
> 阶段：v0.1（VPS cron + Web 终端，无推送）

## 人物与初始数据

- **我**（35，家里管数字的事）
- **妈**：高血压，每天测血压
- **女儿**：3 岁，有疫苗本
- **老婆**：记账本

**部署当天（昨晚 22:00）** 我录入初始数据：

- 账本：过去 3 天支出（只有 3 天，无基线）
- 日程：本周安排
- 健康：妈上周血压记录（缺昨天）
- 疫苗：女儿乙脑第二针，预约周四 15:00

## Day 1

### 06:30 — cron 第一次跑

判断层启动，看到：

1. 账本数据只有 3 天，统计基线不足。今天不产生任何"异常类"提议。
2. 确定性规则扫描命中三条：
   - 疫苗预约周四 15:00，我的日历周四 14:00-16:00 有"季度评审会"——**冲突**
   - 妈血压昨天空缺、今天未测——**连续缺测**
   - 账本"电费"上月 287、本月 403——**基线不足，只记录不提议**

产出：2 条提议 + 1 条观察，写库。

### 07:15 — 我打开 web（马桶时间）

```
┌ 提议 (2) ──────────────────────────────
│
│ ① 周四疫苗预约撞了季度评审会
│    疫苗：周四 15:00
│    你的日历：周四 14:00-16:00 评审会
│    [生成待办：联系社康改时间]
│    [忽略]
│
│ ② 妈的血压昨天没记
│    已连续 1 天缺测，今天还未记录
│    [生成待办：今晚问妈]
│    [忽略]
│
│ ▸ 其他观察 (1)
│
└────────────────────────────────────────
```

我点了 ① 和 ②，各生成一条待办（① 附社康电话——初始数据里有）。

### 21:30 — 我再次打开 web

看到待办"今晚问妈血压"。去问了：140/88，正常。填进健康表单。

mate 明天会看到：缺失补齐，值正常。这条观察归档。

### 22:00 — 影子报告生成（第一周每晚）

今天它看到但没说的：

- 电费环比 +40%（基线不足，只记录）
- 女儿奶粉支出频次升高（基线不足）
- 周五"幼儿园家长会"无地点备注（不知道该不该说，先记录）

## Day 7

信任面板第一行数据：

```
提议 14 条
yes  8     忽略 5     no 1
命中率 8/14 = 57%
被忽略最多：物品临期（5 次忽略 4 次）
→ 自动降权：临期类从"提议"降级"观察"
```

## Day 30

- 电费数据满 30 天，第一个统计异常提议出现
- 临期不再单独提议，攒进周摘要
- 我开始主动补录更多数据（有用的 yes 让我愿意喂数据）

---

## 剧本逼出的设计决策

1. **Day 1 只有确定性规则能开口**（冲突、缺测、临期）。统计异常等基线攒够。价值顺序 = 确定性先行，异常后长。

2. **yes 的语义（v0.1）**：生成待办 + 记反馈。**不做提醒**——v0.1 无推送，待办靠用户打开 web 看。提醒是 v0.2。yes 不承诺"我到时候叫你"，只承诺"我记下了，你在待办里看得见"。

3. **忽略也是信号**：7 天内同类忽略 ≥ 4 次自动降权一级（提议 → 观察 → 归档）。反馈循环第一版是规则不是模型。

4. **影子报告**：每晚生成"看到但没说"清单，第一周每日、之后每周。履职回放雏形，day 1 就有——用户第二天就能核对它滤了什么。

5. **基线阈值显式写死**：电费异常 = 满 30 天数据后环比 >30%。是规则，不是模型自由发挥。

6. **提议结构**：标题（一句判断）+ 事实（两行，可核验）+ 动作按钮。按钮动词来自动作注册表雏形（生成待办 / 忽略）。事实必须可核验——用户点按钮前要能自己判断对不对。

7. **数据录入是产品的一部分**：day 1 初始录入 + 日常表单补录。没有录入就没有 mate。录入表单的质量直接决定判断质量。
