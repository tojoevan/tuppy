## 0. 固件改造（扩展目标，2026-08-16 定案）

**硬件**：微雪 ESP32-S3 2.06" 触控 AMOLED（410×502 QSPI）+ 双麦阵列 + 喇叭。
固件官方支持：`boards/waveshare/esp32-s3-touch-amoled-2.06`。用户有 ESP-IDF 环境 + 固件源码。

**架构**：固件加独立 MQTT 客户端（与官方语音 WebSocket 并行，互不干扰）：

```
官方 server ←WebSocket→ 固件 ←MQTT→ VPS mosquitto ←→ Tuppy
   (语音对话，不动)       (新增：状态/播报/按键)
```

**topic 设计**：

| topic | 方向 | 作用 |
|---|---|---|
| tuppy/status | VPS→固件 | 屏显状态（提议数/健康灯/预算） |
| tuppy/announce | VPS→固件 | TTS 播报（家庭广播） |
| tuppy/button | 固件→VPS | BOOT 键（GPIO 0）短按/长按事件 |

**形态适配**（板子无独立 LED）：

- 桌宠灯态 → AMOLED 屏状态区（状态色块+图标，比灯更富表达）
- 静音键 → BOOT 键长按；触屏手势留后续
- 看板 → 屏显 Tuppy 状态页（提议数/待办数/健康状态）

2. 阶段 1：MQTT 通道 + VPS mosquitto + Tuppy 状态发布 ✅

## 0.1 按键使用指南（已实现部分）

板子两个实体键：BOOT（GPIO 0）+ 电源键（GPIO 待确认）。

**BOOT 键（8 槽位已用 4）**：

| 手势 | 归属 | 功能 |
|---|---|---|
| 短按 | 官方 | 切换对话（开始/停止） |
| 长按 | 官方 | 音量调节 |
| 双击 | **Tuppy** | 静音牌——发布 tuppy/button double，VPS 侧停止推送 |
| 三击 | **Tuppy** | 隐私牌——发布 tuppy/button triple，VPS 侧断听断上报 |

**电源键（AXP2101 PEK，2026-08-16 已实现）**：

> 硬件事实：电源键是 PMIC AXP2101 的 PWRON/PEK 键，不是独立 GPIO。
> 只能通过 I2C 读 INTSTS2（0x49）拿短按/长按 IRQ；双击/三击由软件累计。
> 固件实现：50ms 轮询任务（tuppy_pek），短按事件按时间窗累计；
> 动作统一收口到 TuppyLink::OnPowerKey（屏显通知 + MQTT tuppy/button + 日志）。
> **长按让回 PMIC 原生 4s 关机**（板级 0x27 配置），Tuppy 不占用——避免与关机冲突。

| 手势 | 功能 | 归属 | 状态 |
|---|---|---|---|
| 短按 | Tuppy 语音录入快捷入口 | Tuppy | ✅ 屏显提示"电源键 快捷录入" |
| 双击 | 屏显看板页切换 | Tuppy | ✅ 屏显提示"电源键 看板切换" |
| 长按 | 关机 | 原生(PMIC) | ✅ 硬件 4s 关机，Tuppy 不碰 |
| 三击 | 预留（家庭广播开关） | Tuppy | ✅ 屏显提示"电源键 家庭广播(预留)" |

**待办**：VPS 侧按键语义（double→停止推送一天？triple→怎么断）待设计。

## 1. 主目标：ESP32 语音终端（目标已定案，2026-08-16）

**收敛后的目标**：ESP32 = Tuppy 的语音终端。说进去，问出来。

```
你："今天有什么事"     → 小智 ASR → LLM → MCP list_proposals → Tuppy 查 → 语音答
你："记一笔，牛奶临期" → 小智 ASR → LLM → MCP add_entry → Tuppy 写库 → 语音确认
```

**技术路线**：官方小智服务 + 自定义 MCP（用户已确认官方支持）。不自建 server、不改固件。

**MCP 覆盖范围**：录入 + 查询双向问答是完整闭环（请求/响应天然双向）。

**明确缺口**：Tuppy 主动播报（不请自来地开口）——官方不开放 MQTT 发布。保留：家庭广播愿景留到自建 server 路线（路 C）或智能音箱，不在 v0.3 范围。

### 1.1 MCP 工具集（已定）

**录入类**：
- `add_entry(domain, category, person, happened_at, amount, value, title, note)`——语音录入，entries 带 `source='voice'`

**查询类**：
- `list_proposals`——今天提议 + 状态
- `list_todos`——未完成待办 + 到期标注
- `query_entries(domain, category, days)`——按域/分类/时间范围查
- `weekly_stats`——本周说了几次/命中率/超预算

**明确不暴露**：keep/reject、todo_done、规则增删、数据删除——语音操作不可逆，"判断归你"下口头确认太弱。第一版只读 + 录入。

### 1.2 设计要点（已定）

- **返回格式 LLM 友好**：工具输出短文本摘要（给 LLM 转述），不倒 JSON
- **可审计延续**：语音录入 source='voice'，影子/周报可区分
- **鉴权**：xiaozhi MCP 配置支持 headers 带 token。Tuppy MCP 端验证 Bearer token
- **传输**：streamable-http（生产推荐），公网 URL 走宝塔反代
- **部署**：VPS 独立进程，127.0.0.1 监听 + 反代暴露

### 1.4 观察项（语音阶段新增）

- **LLM 推断 person 准确率**：用户不说主体时 LLM 推断（首例命中：胰岛素→妈妈）。错 3 次以上 → 智控台提示词加"禁止推断 person"约束
- 语音录入的域/分类解析质量：LLM 给的 domain/category 是否合理（首例：更换胰岛素针头 → 健康·胰岛素，合理）
- 语音日期解析：相对日期（明天/下周三）误录率

**2026-08-16 首测记录**（设备实机验证）：
- ✅ 链路通：说"记一笔…"→ ASR → LLM → MCP add_entry → SQLite，source=voice 落库（id=7 牛奶 / id=6 胰岛素）
- ⚠️ **ASR 误识（已确认+已解决）**："记一笔"被 ASR 听成"G比"（屏幕原文即"G比牛奶"），非 LLM/Tuppy 侧。**换触发词 "帮我记一下" 后识别完美**（id=8：title=牛奶、happened_at=2026-08-20 正确解析、category=食品）。以后录入统一用"帮我记一下"
- ⚠️ 日期未解析：说"8/20 到期"但 happened_at=当天——LLM 未把到期日传给 happened_at，观察后续
