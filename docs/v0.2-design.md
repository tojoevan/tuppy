## 3. 待设计项

### 3.1 打扰预算器（主目标，已定设计，2026-08-16）

**两级预算**：

```
规则级（已有，v0.1 降权梯子）= 哪类事值得说——规则的信誉
通道级（v0.2 新增）= 今天整体能吵几次——用户当日的打扰配额
```

两者独立：规则都准但用户最近忙，整体安静。降权管"什么事"，预算管"说多少"。

**默认配额**：每日推送 ≤2（早班 1 + 晚班 1）。周日心跳不算预算（每周存活证明，独立通道）。

**超预算降级**：超出配额的第 N 条 → 不推 → 静默进影子（source_type 复用，文案加"超预算"标注）。

**自动调节**：

```
连续 3 天推送全部被忽略 → 每日配额 -1（最低 1）
连续 5 天推送有响应     → 恢复默认
```

与降权梯子区别：预算看所有推送的整体反应（全局吵不吵），降权看单条规则的反应（某类事准不准）。

**打断级配额**：v0.2 无打断级（无语音/紧急通道），结构留空位，v0.3 ESP32 启用。

**周报呈现**：

```
本周打扰：推了 N 次 / 预算 M 次，你响应 K 次
X 次超预算静默进影子
连续 3 天你没理我（配额自动降为 M-1）
```

**观察项**（运行后验证，暂不改）：

1. 自动调节效果：配额 -1 后用户是否回来响应？（记录每次调整 + 后续 3 天响应率）
2. 降级静默感知：用户能否发现"它有话没说"？（影子页超预算条目是否被注意到）
3. 默认配额 2 是否合适？（周报数据说话）

观察数据来源：proposals 表状态 + 新增 budget_log 表（配额变更记录）。

### 3.2 待办语义（已定设计 + 已实现，2026-08-16）

- **截止时间**：expiry 类提议"记下"时自动带截止（proposals.entry_id → entries.happened_at → todos.due）
- **到期再提醒**：晚班查未完成待办 due ≤ 今天 → 推送"到期了还没处理"（占预算，超预算静默进影子）
- 勾掉 = 归档（已有）
- 待办页显示截止 + 已到期红色标注

**观察项**：8/21 信用卡第一次真触发后，看提醒是否及时、是否烦。

### 3.3 信任面板 v0.1（已定设计，2026-08-16）

**v0.2 范围：不建独立页，揉进现有页面。** 两处：

1. **周报加"命中率趋势"**：最近 8 周每周一行（周 / 说了 N 次 / 命中率%）。趋势比单点数字更有信息量——用户能看到"它在变准"
2. **规则页加"命中率"列**：每条规则历史 proposals 的 kept/(kept+rejected+expired)。样本 <5 显示"—"（少样本不给数字，防误导）

**观察项**：

- 用户是否需要独立面板页（周报内嵌趋势够不够）
- 按周 vs 按月（周粒度先跑，观察用户阅读习惯）
- 规则命中率是否影响用户导入/删除规则的决策
