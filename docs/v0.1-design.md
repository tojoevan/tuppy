# Tuppy v0.1 设计文档

> 状态：**构建唯一参照**。写代码时所有决策以此文档为准。
> 愿景与原则见 [architecture.md](architecture.md)，voice 参照 [day-script.md](day-script.md)。
> 决策标记：⚠ = 暂定推荐方案，后期可变更。

## 1. 范围

- 一个用户：你自己
- 输入：手动录入 + 导入（CSV/ICS）
- 判断：纯规则引擎，无模型调用
- 输出：提议页 + 待办 + 影子报告 + 周报
- 部署：VPS，Flask 单端口，Basic Auth

**明确不做**：推送、多用户、安卓、ESP32、语音、小程序、模型调用、聊天框。

## 2. 交互模型

三个动作，五个页面，无聊天框：

```
选择 → 按钮（记下 / 不用）
输入 → 表单（账本 / 日程 / 健康 / 导入）
查看 → 提议、待办、影子报告、周报
```

页面 = 家，不常驻。用户打开 = 串门，Tuppy 不找用户。

## 3. 数据模型

六张主表 + 三张辅助表（实现时发现必须，见修正记录）：

```sql
entries   -- domain自由文本, category自由文本, person, happened_at, ended_at,
          -- amount, value TEXT, title, note, status, source
rules     -- id, kind(habit|detection), domain, category, template,
          -- params JSON, priority, status
proposals -- id, rule_id, text, status(pending/kept/rejected/expired), shift
todos     -- id, proposal_id, text, done, created_at, done_at
shadow    -- id, date, item_text, rule_hint, source_type, rule_id
health    -- id, date, shift, status, error
rule_log  -- 规则状态变更日志（周报"我学到的"数据源）
import_staging -- 导入暂存（预览确认后落库）
```

- **domain 自由文本**（家庭/工作/学习/健康/财务/物品……），表单给种子下拉 + 自定义
- **value 统一 TEXT**，解析方式由 habit 规则 `value_type` 声明（number/ratio/duration/text/amount）
- **无 users 表**（单人，鉴权不建表）、**无 feedback 表**（proposals.status 即反馈）、**无 extra JSON 列**（YAGNI，真需要再 ALTER）
- 新域接入 = 录数据 + 加 habit 规则行，零 schema 改动

**实现修正（v0.1 开发中记录）**：

1. `shadow` 加 `rule_id` 列——影子"明天开始说这些"需要按规则升权，rule_hint 文本不可靠
2. 新增 `rule_log` 表——周报"我学到的"需要变更历史，rules 表本身无日志
3. 新增 `import_staging` 表——导入预览需跨请求暂存，cookie 装不下

## 4. 规则引擎

### 4.1 结构：模板 + 参数实例 + 解释器

```
L1 模板层：模式（缺测/冲突/突变/到期/异常）
    ↓ 参数化
L2 规则层：参数实例（rules 表一行）
    ↓ 运行
L3 引擎：解释器循环，按 priority 出提议
```

规则是表不是代码。新场景 = INSERT 一行，调优 = 改 params/priority。

### 4.2 v0.1 激活 4 种模板

| 模板 | 参数 | 触发 | 文案 |
|---|---|---|---|
| **缺测 gap** | `{"frequency":"daily|weekly|monthly","max_gap":2}` | `now - 最近记录 > 周期×max_gap` | "{person}的{category}有{N}天没记了" |
| **冲突 overlap** | `{"check_between":"same_person|any","min_overlap_min":0}` | 时间区间相交 | "{titleA}撞了{titleB}（{事实}）" |
| **突变 surge** | `{"compare":"prev_month","ratio":1.3,"min_history_days":30,"min_amount":50}` | 数据天数≥min_history_days 且环比>ratio 且差值>min_amount | "{category}比上月高{pct}%（{上月}vs{本月}）" |
| **到期 expiry** | `{"days_before":3,"recurring":false}` | `到期日-now ≤ days_before` | "{title}还有{N}天到期" |
| 异常 anomaly | — | — | **v0.1 不激活**，推迟 v0.2+ |

- habit 规则注册 (domain, category) 的记录习惯：frequency、value_type、阈值
- 缺测分班：早班扫当天该测未测，晚班扫更早缺口汇总一条
- 冲突：person 为空的两件事仅 any 模式触发，避免噪音
- 突变：比例 + 绝对额双控（min_amount 拦小钱波动）
- 到期 recurring：缴费类到期后自动顺延周期；物品类标记 done 后不再盯
- ⚠ min_history_days=30 全 category 统一，不做 per-habit 配置

## 5. 提议与反馈

### 5.1 三按钮语义

```
[记下] = 接受：proposal.status=kept + 生成 todo
[不用] = 拒绝：proposal.status=rejected
[忽略] = 用户不理：pending 保持 24h 后自动 expired
```

- 点"记下"后按钮原地变"已记下 ✓"（不消失）
- rejected 提议从页面消失，进历史可查

### 5.2 降权梯子

```
提议(propose) ← 新规则默认
  ├ 连续 4 次 expired → 观察(observe)
  ├ 连续 3 次 rejected → 观察
  │
观察：不开口，只进影子报告
  ├ 影子中连续 2 周无任何反馈 → 归档(archive)
  └ 用户手动操作（影子页"明天开始说这些"）→ 升回提议
归档：沉睡，可手动复活
```

- 降权要连续，单次误报不惩罚
- rejected 比 expired 降得快（3 vs 4）——明确拒绝信号强
- 有升权路径，非单行道。归档 ≠ 删除，守可逆转原则

### 5.3 消化时机

全部晚班批处理。白天按钮只写状态，22:00 统一算权。可回放、可审计。

### 5.4 提议限额

早班最多出 3 条，按规则 priority 排序。第 4 条起进影子（source_type=挤掉）。

## 6. 影子报告

### 6.1 什么进影子（四类）

| source_type | 含义 |
|---|---|
| 挤掉 | 规则触发但被 3 条限额挤出 |
| 低于阈值 | 触发但不够格（+20% < 30%） |
| 基线不足 | 数据天数 < min_history_days |
| 未决 | 引擎拿不准，先记着 |

### 6.2 生成与保留

- 晚班生成，只含当天。保留全部历史可翻旧日
- 第一周每天生成；第 7 天后改周报附"本周重要未说 top 5"
- **影子 = 观察状态的可见实现**。降权规则的产出只出现在这里

### 6.3 表态方式

不逐条表态，只有两个整体按钮：
- "明天开始说这些"（选定规则升回提议）
- "继续沉默"

## 7. 周报

### 7.1 生成时间

周日 22:00 晚班，一周第一天 = 周一。

### 7.2 固定五段

```
① 本周数字   说了N次/听进去N次/没理N次/说不用N次（给数字不给百分比，不评判）
② 我学到的   本周规则状态变更列表 + 原因（"临期降权了，因为你4次没理"）
③ 影子 top5  本周看到没说里最重要的 5 条
④ 待办催一下 记下但没勾掉的
⑤ 下周预告   预算对比一句话（"下周我少说一点，说准一点"）
```

- 数据源：proposals + rules 两表聚合，无新字段
- 自动降权必须说明原因——偷偷变会毁信任

## 8. 待办

- 唯一来源：点"记下"。文本抄提议文案，关联 proposal_id
- 能力只有四个：显示、勾掉、归档、周报催
- **明确不做**：截止时间、提醒、编辑、排序、删除
- 勾掉 = done + done_at，进历史。勾掉不影响规则权重（v0.1 不采集勾掉速度）
- 认知：待办是提议的落点，不是独立 todo 系统

## 9. 导入

- 格式：CSV（账本/健康/物品）+ ICS（日程/到期）
- CSV 首行 header = 字段名，缺列默认值，多列忽略；日期宽容解析；解析失败行跳过并汇总报告
- ICS 用 `icalendar` 库，取 SUMMARY/DTSTART/DTEND/LOCATION/DESCRIPTION，domain 归 schedule，person 导入时统一问一次
- 流程：选文件 → 预览页（N 行写入，M 行失败）→ 确认落库
- 去重：⚠ (domain, person, happened_at, title, amount) 五元组相同 = 跳过
- 不做：自动对接银行 API、自动同步

## 10. 鉴权

**实现修正（2026-08-16）**：Basic Auth 弃用，换 Flask 登录页：

- `/login` 登录页 + 签名 session cookie（30 天，可登出）
- 密码 `.env` TUPPY_PASSWORD（独立于 TUPPY_SECRET），hmac.compare_digest 比对
- app 启动时自读 .env 合并环境（systemd 注入不可靠）
- `/static/` 免鉴权（PWA 图标/清单不被挡）；其余全锁，未登录 302
- 弃用原因：PWA standalone 下 Basic Auth 弹窗缺陷、无登出、无过期

## 11. 失败模式

| 失败 | 处理 | 用户感知 |
|---|---|---|
| cron 没跑 | 下一班检测，health 记一条 | 页面黄条"昨晚没上工，今天补上" |
| 单条规则报错 | try/except 包每条规则，不影响整班 | 黄条"1 条规则报错，详见影子" |
| 数据库损坏 | 每日晚班后 VACUUM + 备份轮转 7 份 | 运维层面，页面不显示 |
| 服务挂 | systemd 托管自动重启 | 用户自然发现（打不开页面） |

- 页面顶部固定健康灯：● 绿（两班正常）/ ● 黄（缺席/报错）/ ● 红（自检失败）
- 早班开头自检三件事：昨晚晚班跑了吗、有报错吗、行数突变 >20% 警告
- 黄条警告 v0.1 只在页面显示，不推送（v0.2 推送上线后进白名单）

## 12. 技术栈

```
Python 3 + Flask + Jinja2
sqlite3 裸用（无 ORM）
系统 crontab ×2（06:30 早班 / 22:00 晚班）
nginx（Basic Auth + 反代，可选）
systemd（托管 Flask）
前端无框架无构建，PWA 图标可选
```

- 无 Docker、无队列、无 APScheduler、无模型调用
- 总量约 500-800 行，一周业余时间
- 结构：`app.py`（路由）、`engine.py`（模板解释器）、`schema.sql`、`templates/`（五页）

## 13. 两班职责

```
06:30 早班：自检 → 读新记录 → 跑活跃规则 → 排序限额3条 → 写 proposals
22:00 晚班：处理反馈降权 → 生成影子报告 → 周日加周报 → 备份 DB
```

## 14. 完成的定义

三项全过才算 v0.1 完成：

1. **技术完成**：六表 + 四模板 + 五页面按本文档实现，无遗留 TODO
2. **连续运行**：VPS 跑满 14 天零手动干预，health 全绿（规则报错允许，cron 缺席不允许）
3. **真实使用**：
   - 录入 ≥30 天跨度数据（含导入）
   - 提议接受率 ≥30%
   - 打开影子报告 ≥5 次
   - ⚠ 页面访问间隔 >3 天 = 停用，判据不改

达成后：写 CHANGELOG 记录实际数字，由 14 天使用摩擦决定下一步（加域 / v0.2 推送 / 打磨规则）。

## 16. 已拍板（不可变）

- 无聊天框，三动作五页面
- 纯规则，无模型
- 域自由文本 + habit 参数化
- 四模板激活，anomaly 推迟
- 降权梯子：4 expired / 3 rejected → 观察 → 2 周无反馈 → 归档
- 提议限额 3 条
- 影子四类 source_type
- 待办无编辑无删除无截止
- Basic Auth，密码在 .env
- 完成定义三项判据
