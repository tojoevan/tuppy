# Tuppy v0.2 设计文档

> 状态：**进行中**。已定项写死，未定项如实标注。v0.1 参照 [v0.1-design.md](v0.1-design.md)（已固化）。

## 1. 范围

**主目标**：推送完整版 + 打扰预算器。

**附带**（判据期暴露的遗留）：

- 待办语义深化（截止/再提醒）
- entries 历史分页
- 数据导出按钮
- 日志轮转
- 规则单条删除
- 信任面板 v0.1（命中率可视化）
- 周报节奏调整（第 7 天后影子降频，设计文档 §6.2 定了但未实现）

## 2. 已定项（继承 v0.1，不可变）

- 无事不推；一天最多两班推送 + 周日周报心跳
- 推送通道：ntfy（127.0.0.1:2586，Click 跳转）
- 提议限额 3 条/班，影子报告四类
- 降权梯子：4 expired / 3 rejected → 观察 → 2 周无反馈 → 归档
- 登录页鉴权、规则生态、seed 生成管线不变

## 3. 待设计项

### 3.1 打扰预算器（主目标，未设计）

当前"无事不推"是天然预算。v0.2 需要回答：

- 显式每日预算上限？（如每天最多 N 条推送）
- 预算按什么粒度记？（按推送条数 / 按规则 / 按打扰级别）
- 超预算降级路径？（推送 → 摘要 → 影子）
- 预算数据进周报/信任面板怎么呈现？
- 与降权梯子（规则级）的关系——预算是通道级还是规则级？

**待讨论。判据数据（接受率）应参与设计**——8/30 前先讨论，数据出来后校准。

### 3.2 待办语义（挂起中，等 8/21 体感）

用户 8/21 收到第一条真提议（信用卡到期）。"记下"生成的待办：

- 要不要截止时间？（提议本身有日期，如"信用卡还有 2 天到期"）
- 要不要到期再提醒？（v0.1 决定不提醒，靠提议重复）
- 勾掉 vs 归档的区分
- 待办与提议的关联展示（"这条待办来自哪个发现"）

**待用户真实使用后定。**

### 3.3 信任面板 v0.1（未设计）

周报已有数字（说了 N 次/听进去 N 次）。信任面板加什么：

- 命中率时间线（周粒度）
- 按规则聚合的接受率（哪些规则准，哪些吵）
- 与规则页联动？（规则页显示每条规则的命中率）

**待讨论。数据源已具备（proposals + rules），是纯展示层。**

## 4. 附带项设计要点

| 项 | 要点 |
|---|---|
| entries 历史分页 | 录入页"最近 10 条"加"加载更多"/按域筛选。简单分页即可 |
| 数据导出 | "数据是文件"兑现。下载完整 SQLite 或 CSV。一个路由 |

| 规则删除 | 规则页单条删除（带确认）。与 tuppy-rules 导入的规则同待遇 |
| 周报节奏 | v0.1 设计 §6.2：第 7 天后影子改周报 top5。引擎晚班生成逻辑加条件 |

## 6. 判据联动

14 天判据 8/30 出结果：

- 接受率 ≥30% → v0.2 按本文档推进
- 接受率 <30% → v0.2 优先调规则/提议质量，预算器和面板靠后
- 停用（>3 天未访问）→ 先查为什么不用，再谈功能
